# Анимационный этап 0.38 — спецификация кандидата

Текущий принятый технический baseline: сборка 0.37. Художественная приёмка
движения отсутствует. Пользователь отметил дёрганость; ускоренный Run вместо
уклонения и отсутствие отдельного hurt подтверждены исходником actor.gd.

Цель этапа: сохранить существующие модель, пропорции, одежду, шарф, сумку и
ключ Артёма, заменить неудачное движение проверенными скелетными клипами.
Новый дизайн лица/тела не предлагается. Оригинальные GLB не перезаписывать
до проверки кандидата в Godot. Не менять темп управления ради длинного клипа.

Источник кандидатов: Quaternius Universal Animation Library Standard, CC0,
уже сохранённый официальный пакет source_25d/ual-standard. 63 кости источника
и 31 кость рабочего Man не совместимы напрямую. Нужна явная таблица и
поправка rest-матриц, без scale-анимации конечностей.

Порядок: inspect двух ригов → нейтральные/крайние позы → in-place walk/jog/
sprint → отдельные roll/hit/death → GPU-сравнение → интеграция контроллера
и переходов → обычный ввод и связанные проверки. Проваленный кандидат
остаётся кандидатом, наличие названий клипов не является приёмкой.

Контракт: контроллер двигает CharacterBody3D, клип — позу; никакого двойного
root motion. Сохранять длины костей, ладонь/ключ и одинаковый масштаб. Сверить
фазы опоры и скольжение в метрах. Не выдавать свободный перенос стопы за
скольжение опоры. Хват правых пальцев сохраняется между состояниями.

Для уклонения сравнить продолжительность и ключевые позы реального Roll с
существующим рывком 0.18 с / 11 м/с. Не сжимать 1.47-секундный кувырок в 0.18 с.
Если требуется другой тайминг, сохранить пройденное расстояние/быструю реакцию,
разделить фазу неуязвимости, физическое перемещение и визуальное восстановление.
Проверить возможность двигаться/атаковать после восстановления и частый ввод.

Матрица проверки: игровой и близкий фиксированный ракурсы; idle→walk→run→stop,
диагонали, 180°, стоячий/движущийся/повторный удар, уклонение, hurt, death до
последней позы, pause/resume, 30/60/120 render FPS при физике 60, руки с носилками.
Actual GPU screenshots + footage, последовательные кадры границ и контактные
метрики. Численные допуски и ограничения публиковать вместе с результатами;
не объявлять качественной всю анимацию по одному удачному ролику.

Основание API: установленный Blender 5.1.1, bpy Bone.convert_local_to_pose;
Godot 4.7.2, существующий AnimationTree. Официальные справки:
https://docs.blender.org/api/5.1/bpy.types.Bone.html
https://docs.godotengine.org/en/stable/tutorials/animation/animation_tree.html
